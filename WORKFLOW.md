# Repo Update Workflow

## Golden rule — NEVER use these commands
```
git reset --hard          # wipes all local files
git checkout -- .         # same
git rebase (without care) # can conflict on binary files
```

## Correct update flow every time

### 1. Always start by pulling first
```bash
cd "/Users/bebo/Desktop/FWrange new testing/sileo-repo"
git pull origin main
```

### 2. Make your changes
- Add/replace a `.deb` in `debs/`
- Edit `depictions/` JSON if needed
- Edit `build_repo.sh` if adding a new package

### 3. Rebuild the Packages index
```bash
bash build_repo.sh
```

### 4. Commit and push
```bash
git add -A
git commit -m "v1.0.18 — short description"
git push
```

If push is rejected ("remote contains work"):
```bash
git pull --rebase origin main
git push
```

## Adding a new package

1. Drop the `.deb` into `debs/`
2. Add its icon/depiction entries in `build_repo.sh`:
```bash
pkg_icon() {
  case "$1" in
    com.fwrange.payrangehook)   echo "assets/payrangehook.png" ;;
    com.qiop1379.iflooder)      echo "assets/iflooder.png" ;;
    com.your.newpackage)        echo "assets/newpackage.png" ;;   # ← add here
  esac
}
pkg_depiction() {
  case "$1" in
    com.fwrange.payrangehook)   echo "depictions/com.fwrange.payrangehook.json" ;;
    com.qiop1379.iflooder)      echo "depictions/com.qiop1379.iflooder.json" ;;
    com.your.newpackage)        echo "depictions/com.your.newpackage.json" ;;   # ← add here
  esac
}
```
3. Create `assets/newpackage.png` (512×512 icon)
4. Create `depictions/com.your.newpackage.json` (copy an existing one and edit)
5. Add to `sileoFeatured.json` if you want it featured
6. Run `bash build_repo.sh` → commit → push

## Bumping PayRange hook version

1. Edit `deb_build/DEBIAN/control` — bump `Version:`
2. Rebuild dylib if there are code changes (compile + ldid + lipo)
3. Build the new `.deb`:
```bash
cd "/Users/bebo/Desktop/FWrange new testing"
dpkg-deb --build --root-owner-group deb_build \
  "com.fwrange.payrangehook_1.0.XX_iphoneos-arm64.deb"
```
4. In the repo folder:
```bash
git pull origin main
rm debs/com.fwrange.payrangehook_1.0.OLD_*.deb
cp ../com.fwrange.payrangehook_1.0.XX_iphoneos-arm64.deb debs/
bash build_repo.sh
git add -A
git commit -m "v1.0.XX — what changed"
git push
```

## Repo structure (don't delete these)
```
CydiaIcon.png              ← repo icon in Sileo sources list
Release                    ← repo metadata (don't touch)
Packages                   ← auto-generated by build_repo.sh
Packages.gz                ← auto-generated by build_repo.sh
sileoFeatured.json         ← featured banner at top of source
build_repo.sh              ← run this every time before pushing
debs/                      ← all .deb files
assets/                    ← package icons (512×512 PNG)
depictions/                ← per-package detail pages (JSON)
```

## Privacy — keeping debs from being crawled

GitHub public repos are indexed by Google and Cydia scrapers.
Options to limit exposure:
- **Rename debs** to non-obvious filenames (the Filename: field in Packages still points correctly)
- **GitHub Actions secret** — you can add a password check to the repo (see below)
- **Move to private repo** with a GitHub token-authenticated raw URL (Sileo supports `https://token@raw.githubusercontent.com/...`)

### Private repo workaround (most secure):
1. Make the GitHub repo **Private**
2. Create a fine-grained PAT with read-only access to that repo
3. In Sileo add source as: `https://raw.githubusercontent.com/fwbebofficial/fwrange-repo/main/` with the PAT embedded — but Sileo doesn't support token auth natively
4. **Best option**: use the VPS approach (fwchecker.online) which is not publicly indexed
